# Plan: Fix Stream and Tool Call Issues for llama.cpp Integration

## Issues Identified

### 1. Critical Bug in `chatCompletion` Function (Non-Streaming)
**Location:** `src/lib/ia/client.ts`, lines 92-100 and 120-126

**Problem:** 
- The function prepares a `body` variable with `tools` and `tool_choice` parameters (lines 92-100)
- But then creates a NEW body object on lines 120-126 that DOESN'T include these parameters
- This means tool calls are never sent to the llama.cpp server
- The function tries to handle tool calls in the response (lines 145-203), but they never arrive because they weren't requested

**Current Code (lines 114-127):**
```typescript
const response = await fetch(`${config!.endpoint}/chat/completions`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${config!.api_key}`,
  },
   body: background-color:
    model: config!.model_default,
    messages: messages,
    max_tokens: config!.max_tokens,
    temperature: config!.temperatura,
    stream: false,
  }),
});
```

**Fix - Replace with:**
```typescript
const response = await fetch(`${config!.endpoint}/chat/completions`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${config!.api_key}`,
  },
  body: JSON.stringify(body),
});
```

**Impact:** 
- Tool calls (like `buscar_dados_usuario`, `render_dashboard`, etc.) don't work in non-streaming mode
- The route falls back to using non-streaming mode inside a fake stream (line 89 in route.ts)

**Current Code (lines 351-362):**

**Recommendation:** Add logging to verify the format of tool calls from llama.cpp and handle both OpenAI and llama.cpp formats.
